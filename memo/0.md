# テキスト問題

　2026年現在、人類はコンピュータ上でテキストを扱うあらゆる場面において致命的な問題を抱えている。それは世界標準Unicodeによってもたらされている。

1. セキュリティ問題（ヌルバイト攻撃、不正なバイトシーケンス、正規化の問題（ホモグラフ攻撃等））
2. ローカライズ問題（CJK統合漢字など）
3. パフォーマンス問題（1,2を解決するのは非現実的）

　Unicodeは世界中の文字を単一規格で表示するという目標をほぼ達成している。かつて国ごとに異なる文字セットを使っており、インターネット上においてはしばしば文字化けしてしまい、情報交換できない問題があった。Unicodeはこれを解決した。偉大な仕事だが、それと同時に致命的な技術負債となってしまった。

　Unicodeはあまりにも色々な機能を詰め込みすぎた結果、セキュリティ問題に発展している。その原因は文字のバイナリマッピングという文字セット本来の仕事とは無関係の機能を前提としたコードポイントを盛り込みすぎた結果である。

　これを解決するには印字可能文字以外のコードポイントを完全に排除した新しい文字セットを作る必要がある。当然、文字化けせぬよう、かつ印字可能以外の空白・制御コードも必要に応じて使えるようにする必要がある。これを実現するためには、もはや事前定義した単一のマッピング表では対応できない。もっと複雑な工程が必要になる。

　これはテキスト革命になる。現代に至るまで「テキストとは文字セット定義されたコードポイントの配列である」というのが常識だった。これを変えねばならない時期に来ている。

　現代においてUnicode問題は、多層的に責任分離して実装すべきと私は考える。たとえば以下のように。

1. 文化定義層（国、言語、文脈を定義する。自然言語（国、言語）、文脈（数学、音楽、…））
2. 文字セット定義層（1の分類内でコードポイントを割り振る。印字文字以外の空白・制御は一切なし）
3. 使用文字セット宣言層（2の中から選びサブ文字セットを作る）
4. 文書構造定義層（文書構造によって必要な空白・制御を定義する）
5. 使用文書構造宣言層（使用したい文書構造（空白・制御コード）を選択する）
6. ファイル作成する（3,5でサブ文字セットが確定する。アプリによって適時適切にコードポイントを付与する）

## 世界標準Document規格

人は様々な文脈でテキストを用いる。その文脈によって必要な文字が違う。逆に言えば、文脈を特定すれば必要な文字も特定できる。ならばその文脈を統一規格にしてしまえば、必要な文字も定まる。

残念ながら未だ世界には使用文字を特定する文脈を定義した規格など存在しない。そこで、この大いなる仕組みの体系化をここで計画する。

1. 文化定義層（国、言語、文脈を定義する。自然言語（国、言語）、文脈（数学、音楽、…））
2. 文字セット定義層（1の分類内でコードポイントを割り振る。印字文字以外の空白・制御は一切なし）
3. 使用文字セット宣言層（2の中から選びサブ文字セットを作る）
4. 文書構造定義層（文書構造によって必要な空白・制御を定義する）
5. 使用文書構造宣言層（使用したい文書構造（空白・制御コード）を選択する）
6. ファイル作成する（3,5でサブ文字セットが確定する。アプリによって適時適切にコードポイントを付与する）
7. 圧縮層（バイナリデータを圧縮する層）
8. 暗号化層（バイナリデータを暗号化・復号化する層）

大まかに言えば以下のような構造。

* 文脈（文脈（自然言語（国、言語）、専門分野（数学、音楽、…）、プログラミング言語（C言語、Python、…）、構造化テキスト（CSV, XML, JSON, YAML, …）））
    * 文字セット（`ID: 文字セットID`, 文字セット内コードポイント）
* 文書構造（文（空白制御皆無）、文章（スペース有り）、簡易文書（改行、TAB有り）、本格文書（見出し、段落などの構造用コード有り））
    * 空白・制御コードセット
* ファイル作成
* 通信・展開
